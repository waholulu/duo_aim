# 采集卡画面 → 中心区域识别 → KMBox 鼠标修正

默认自动查找 KMBox B+/B Pro 的唯一 USB 串口，适应插拔后的端口名称变化。存在多个 USB 串口时需用 `--serial-port` 指定。实体鼠标需插在 KMBox 的鼠标输入端，KMBox 的输出端连接目标 Windows 电脑。程序读取 `km.left()` 的**物理左键**状态：只有按住左键才执行图像预处理、YOLO 推理和自动瞄准；检测到松开后丢弃待处理结果，不再发送移动。原本的物理左键事件仍由 KMBox 正常转发，程序不会代替用户点击或开火。

## 启动

```sh
# 先看日志，不发送鼠标移动；同样只在按住物理左键时识别
./start_aim.command

# 确认画面和识别结果后，启用 KMBox 相对移动
./start_aim.command --live

# 如串口名称不同，明确指定
./start_aim.command --live --serial-port /dev/cu.usbserial-120
```

Ctrl+C 停止。终端每半秒最多显示一次 `head`（采集画面坐标）、`error`（到画面中心的偏移）和 `dx/dy`（鼠标相对移动量）。完整日志保存至 `results/aim-日期-时间.jsonl`。`no_target` 表示当前没有合格头部，`confirming` 表示等待连续帧确认，`move` 表示通过输出前检查的移动，`output_status=simulated` 为模拟发送，`sent` 为实际发送，`aligned` 表示已接近中心。启动不需要 Mac 辅助功能权限。

采集卡继续接收完整的 1920×1080 帧，但模型**只分析中心 960×960 像素**，不会把全屏缩放后识别。画面中心目标半径默认 300 像素；`--crop` 可调整中心正方形裁剪边长（1–1080），`--radius` 不得超过裁剪边长的一半。输出坐标映射回 1920×1080 原图，瞄准参考点是原图中心。

## 调整

```sh
./start_aim.command --live --gain-x 0.15 --gain-y 0.15 --max-step 32
./start_aim.command --live --crop 800 --radius 250
```

默认按发送开始时间每 25 ms 最多移动一次，每轴最多 32 计数，误差 3 像素内停止。像素偏差不是鼠标计数，实际游戏灵敏度需后续标定。YOLO 使用鼻尖作为头部代理点，不能保证在烟雾、遮挡或小目标上可靠识别。

左键查询间隔设置为至少 10 ms；2026-10-02 现场只读观测 20 秒取得 988 次采样，实际约 20 ms 一次，识别到 32 次按下及 32 次松开。检测器在左键松开时仍接收采集卡回调，但不做裁剪、模型推理或结果输出；下一次按下会重新开始确认目标。发移动指令前再查询一次左键状态；串口查询失败会中止运行。串口会话独占，不能同时运行其他 KMBox 控制脚本。未在真实游戏中验证最终瞄准效果或按键释放时延。

原有 Mac 和 UDP 输出仍可显式使用：`--backend mac --activation hold-right`、`--backend udp --activation auto`。它们不读取接在 KMBox 上的物理左键。Windows 接收器的设置仍见 `windows_receiver.py`；KMBox 默认模式不需要它。

## 启动、时效性和故障

检测器在模型与采集配置完成后报告 `ready`。启动等待上限为 120 秒；激活后连续 5 秒没有有效帧或预热进展会停止运行并返回非零退出码。待机允许没有检测输出。`--seconds` 是整个运行时长上限，可在就绪前结束，不能将短时运行正常结束单独视为推理通过。

首次按住按键后完成 30 次成功推理预热，这些结果不参与控制。松开期间不推理，再次按下继续剩余预热；同一检测进程只预热一次。空检测帧是正常进展，不等同于断流。

发送前再次读取激活状态，然后用原始 PTS 检查帧龄（默认不超过 80 ms）、epoch 与发送间隔。查询期间变旧的结果记为 `stale_before_move`，查询发现松开记为 `released_before_move`，二者均不消耗发送间隔。按键切换清空待处理结果并重置连续确认，但不取消上次发送的限频约束。非有限时间值或超过 5 ms 的主机时钟负偏差会中止运行。

检测模式也走相同输出前检查，并提交模拟发送。默认 KMBox 按键方式不变；Mac 检测模式现在也遵守指定的按键方式，持续检测应显式选择 `--activation auto`。UDP 的激活仍由 Windows 接收端控制；这里的帧龄仅约束本机发送时刻，未修改远端协议，也不代表远端执行时的完整时效保证。

输出失败、异常流、子进程退出、激活断流或控制管道堵塞会停止追加输出并关闭资源；不自动重连。退出直接终止检测进程，再关闭管道，避免清理过程等待已失去响应的检测器。检测器发现父进程输入管道关闭时也会退出并释放采集。运行时长和 Mac Escape 会在最后一次按键查询后再次检查，停止后不追加发送。首次构建和共享 Swift 源文件更新时，启动器自动重编译。

## 记录与离线回放

```sh
./start_aim.command --seconds 20 --record-replay
# 将下面路径替换为本次运行实际打印的路径
.venv/bin/python aim/replay.py results/aim-YYYYMMDD-HHMMSS-PID.replay.jsonl
.venv/bin/python aim/replay.py results/aim-YYYYMMDD-HHMMSS-PID.replay.jsonl --gain-x 0.1 --gain-y 0.1 --deadzone 4 --confirm-frames 3
.venv/bin/python summarize.py results/aim-YYYYMMDD-HHMMSS-PID.jsonl
```

默认日志首行为 `metadata`，含模型内容 SHA-256、完整策略参数、裁剪、后端、协议版本和是否模拟；不包含 `AIM_TOKEN`。后续有 `ready`、`decision`、`fault`、`stop`，读取日志时应按 `type` 区分，不能假定每行都有 `dx/dy`。

重要字段：

| 字段 | 含义 |
|---|---|
| `output_status` | `not_requested` 无建议；`simulated` 模拟发送；`sent` 实际发送；`dropped` 最终检查丢弃；失败记录在 `fault` 和可选回放输出事件中 |
| `pts_to_controller_ms` | 本帧进入策略时的 PTS 帧龄 |
| `query_ms` | 输出前按键查询耗时 |
| `send_age_ms` | 最终检查时的 PTS 帧龄；只有发送成功行可用于发送帧龄统计 |
| `send_start_s` | 调用输出前的运行相对单调时间 |
| `command_complete_s` | 输出方法返回时间；不是目标画面响应时间 |
| `preprocess_ms` / `inference_ms` / `postprocess_ms` | 共用视觉路径的阶段耗时 |

`--record-replay` 另存完整候选、控制循环实际消费的帧、按键 epoch 变化、决策、输出检查与提交事件。所有 `_s` 时间使用运行起点为零的主机单调时间；输入 PTS 可能小于零。被单槽覆盖、尚未消费的帧不保存，已经消费但 epoch 过期的帧会保存。JSONL 是按执行顺序记录的事件序列，不保存视频。

原配置回放逐行读取记录，核对决策、输出检查、实际发送量及提交时间，发现不一致或缺少结束/故障事件的截断记录时返回非零退出码。参数覆盖比较复用已记录的输入和输出机会；新配置若在原本没有输出查询的帧提出移动，会计为 `no_recorded_output_boundary`，不会编造按键查询结果。此工具不能模拟参数改变后的真实未来画面。未启用记录或旧版日志无法重建完整回放。

汇总输出阶段耗时、成功发送帧龄和间隔的中位数/P95，及过期、释放丢弃、故障次数；模拟发送和实际发送在 `output_statuses` 中区分。串口返回只代表命令交互完成，不代表画面反馈已到达。

## 手动标定

先完成设备检查、检测模式记录和可信目标确认。真实移动仅在你手动选择 `--live` 后执行；以下流程不自动发送校准动作、不自动更改增益。

1. 在可重复、静止的测试场景记录目标程序、分辨率、FOV、灵敏度、鼠标 DPI、模型和裁剪尺寸。关闭或记录会改变映射的加速度设置。
2. 静止画面保持检测，使用回放候选观察鼻尖在固定目标上的像素波动，区分检测抖动与真实移动。
3. 在受控场景手动进行少量、隔离的移动试验，记录发送计数与动作稳定后的同一目标像素位置；分别计算 x/y 的像素变化除以鼠标计数。方向、幅度和多次重复都需要检查，目标身份必须保持一致。
4. 用独立可观察标记或录像识别动作发生与采集画面首次响应，记录时间分辨率及误差范围。仅靠串口确认和当前日志不能测出完整物理反馈延迟。
5. 将结果填入 [标定记录模板](calibration-template.csv)，副本保存在 `results/`。结合反馈延迟、抖动及是否过冲，手动选择下一次 `--gain-x/--gain-y`；默认增益保持 0.15。

验收真实闭环需要实际场景中的收敛、过冲、目标切换和按键释放观测。合成延迟测试通过只证明指定模拟条件下的行为，不替代这些测量。

## 内部协议与构建

流式检测器 stdout 为协议版本 1 的 JSON 行，stderr 为诊断文本：`ready` 含模型尺寸和 30 次预热总量；`warmup` 含当前完成次数及 `gate_epoch`；`frame` 保留尺寸、裁剪、完整检测和计时字段，追加 `type` 与 `protocol_version`。Python 校验结构、有限数值、尺寸、事件顺序与实际预热进度。stdin 仍为 `0|1 epoch`。

```sh
swiftc -O aim/VisionCore.swift aim/detector.swift -o aim/detector
```

benchmark 与检测器必须同时使用当前的公共核心构建；协议升级后不能混用旧检测器二进制。
